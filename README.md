# Ramedas Reports Agent

Система автоматичного збору, розпізнавання, вирівнювання та сортування щоденної фотозвітності шкільних і дошкільних харчоблоків із групових чатів **Viber** і **Telegram** у структуру папок бухгалтерії.

---

## Чекліст впровадження та переходу в бойовий режим

Нижче зібрано все, що потрібно перевірити або дозаповнити перед повним запуском на мережеву папку компанії:

1. **Актуалізувати довідник закладів (`data/facilities.json`):**
   - Зараз у системі завантажено **385 закладів** зі збережених архівів.
   - Щойно бухгалтерія надасть оновлений перелік активних шкіл і садків на поточний навчальний рік, його потрібно оновити в `data/facilities.json`.
2. **Пілот на 3 групах Viber -> масштаб на ~50 груп:**
   - На комп'ютері або сервері має бути відкритий робочий клієнт `Viber Desktop` із підключеним робочим номером, доданим у потрібні групи.
   - Спочатку перевіряємо роботу `--watch` на 3 тестових групах, після чого підключаємо решту (~50) груп Viber.
3. **Увімкнути збереження напряму в мережеву папку сервера:**
   - Зараз для безпеки змінна `REPORTS_OUTPUT_DIR` вимкнена, тому файли складаються локально в `./storage/reports/`.
   - Перед переходом у бойовий режим переконайтеся, що обліковий запис Windows має права запису в мережеву шару, і розкоментуйте в `.env`:
     ```ini
     REPORTS_OUTPUT_DIR=\\ramedas.local\Public
     ```
4. **Підключити Telegram-групи (коли робочий акаунт додадуть у чати):**
   - Отримати `TELEGRAM_API_ID` та `TELEGRAM_API_HASH` на [my.telegram.org](https://my.telegram.org) і прописати їх у `.env`.
   - Виконати разову авторизацію та перевірити доступні групи:
     ```powershell
     .\.venv\Scripts\python.exe -m src.main --telegram-login
     .\.venv\Scripts\python.exe -m src.main --telegram-chats
     ```
   - За потреби обмежити список груп через `TELEGRAM_ALLOWED_CHATS` (ID або частини назв через кому; якщо порожньо - читаються всі групові чати).
5. **Увімкнути технічні сповіщення в Telegram (опційно, рекомендовано на продакшні):**
   - Створити бота через `@BotFather` і вписати у `.env` значення `TELEGRAM_BOT_TOKEN` та `TECH_ALERT_CHAT_ID`.
   - Перевірити доставку командою `--test-alert`. Без цих ключів алерти пишуться в локальний лог і БД, але не надсилаються в Telegram.
6. **Додати додаткові LLM-ключі (опційно):**
   - Зараз підключений `GEMINI_API_KEY` (3 моделі Gemini Flash-Lite у ланцюжку). Для додаткової страховки при піковому навантаженні ~50 груп у `.env` можна додати `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` або `OPENROUTER_API_KEY`.

## Структура папок бухгалтерії та іменування файлів

Усередині кореневої папки (`REPORTS_OUTPUT_DIR`, або `./storage/reports/` якщо вона не задана) формується дерево для бухгалтерії:

```text
<REPORTS_OUTPUT_DIR>/
└── Щоденні документи/
    └── <Громада>/
        └── <Скорочена назва закладу>/
            └── <YYYY-MM Місяць>/          (напр. 2026-11 Листопад)
                └── <YYYY-MM-DD>/          (дата самого документа)
                    ├── 2026-11-20_Акт_<id>.jpg
                    ├── 2026-11-20_Щоденний_звіт_<id>.jpg
                    ├── 2026-11-20_ТТН_<id>.jpg
                    └── Контрольна порція/
                        └── 2026-11-20_Контрольна_порція_<id>.jpg
```

### Типи документів та назви файлів
| Тип у системі (`document_type`) | Префікс у назві файлу | Призначення |
| --- | --- | --- |
| `act` | `Акт` | Акт харчування / акт виконаних послуг |
| `daily_report` | `Щоденний_звіт` | Щоденний звіт про харчування / меню-відомість |
| `menu` | `Меню` | Меню-розкладка на день або тиждень |
| `application` | `Заявка` | Заявка на продукти |
| `raw_materials_calc` | `Розрахунок_сировини` | Розрахунок потреби в сировині |
| `waybill_internal` | `Накладна` | Внутрішня видаткова накладна (напр. зі складу Луцьк) |
| `waybill_external` | `ТТН` | Зовнішня ТТН / накладна від постачальників (хліб, молоко тощо) |
| `receipt` | `Чек` | Касовий або товарний чек |
| `food_photo` | `Контрольна_порція` | Фото готових страв (зберігається у підпапці `Контрольна порція/`) |
| `other` | `Документ` | Інший звітний бланк |

### Логіка дат та сервісні папки
- **Дата папки:** береться з самого документа. Для багатоденних або тижневих звітів фіксується **останній заповнений день**.
- **Валідація дати (`DOCUMENT_DATE_MAX_AGE_DAYS=14`):** якщо ШІ прочитав застарілий рік (напр. `2023-11-18` замість `2026-11-18`), рік виправляється автоматично; якщо дата відсутня або виходить за межі дозволеного вікна днів - папка формується за датою надходження фото.
- **Захист спільної папки бухгалтерії:** сумнівні, нерозпізнані або нерелевантні фото **не потрапляють** у `Щоденні документи/`, а складаються окремо локально:
  - `storage/needs_review/<YYYY-MM-DD>/REVIEW_<FAC-XXXX_Назва>_<Тип>_<id>.jpg` - документи з важким почерком або недостатньою впевненістю для перевірки очима.
  - `storage/unmatched/<YYYY-MM-DD>/` (плюс `Контрольна порція/`) - фото без реквізитів закладу (наприклад, одиночне фото тарілки або зведена відомість на весь район).
  - `storage/ignored_non_reports/<YYYY-MM-DD>/` - етикетки сировини, упаковки продуктів, сторонні фото.

## Як усе працює від початку до кінця (9 етапів)

1. **Прийом фото у Viber / Telegram та watchdog (`src/viber_watchdog.py`, `src/connectors/`):**
   - Для Viber використовується десктопний клієнт `Viber.exe`, який автоматично скачує фото з усіх груп у `VIBER_DOWNLOADS_DIR`. `ViberProcessWatchdog` кожні 30 секунд перевіряє процес `Viber.exe` і перезапускає його при падінні.
   - Для Telegram працює `TelegramUserConnector` (`Telethon`), який вивантажує нові фото та нестиснуті зображення-документи в `TELEGRAM_DOWNLOADS_DIR` із дозавантаженням пропущеної історії (`TELEGRAM_LOOKBACK_HOURS`).
2. **Черга, відновлення після простою та батчинг (`src/pipeline.py`, `src/connectors/viber_local.py`):**
   - Черга звіряється з SQLite (`storage/state.db`): уже завершені файли пропускаються, нові (включно з нічними), перервані (`processing`) і тимчасово неуспішні (`failed`, до 5 спроб) стають у роботу.
   - У режимі `--watch` агент чекає `BATCH_WINDOW_SECONDS` (45с) після останнього фото, щоб зібрати альбом, і групує фото окремо по каналах (`viber` / `telegram`) із порогом `<= 6с`.
3. **Дедуплікація за вмістом (`SHA-256`):**
   - До виклику ШІ рахується `SHA-256` байтів файлу. Дублікат у межах пакета або по всій історії позначається як `duplicate` без витрати лімітів ШІ.
4. **Маршрутизація ШІ, Hot-Reload та backoff (`src/llm/router.py`, `src/llm/providers.py`):**
   - `VisionModelRouter` автоматично перечитує `config/llm_routing.json` і `.env` без перезапуску при змінах.
   - При помилках `429` / `503` або таймаутах модель іде в `cooldown` (60с), і запит перемикається на наступний маршрут у ланцюжку. Якщо всі маршрути опинилися в `cooldown`, роутер робить коротку паузу (1-15с) і пробує модель, чий `cooldown` минає найшвидше.
5. **Промпт, класифікація та автоповорот (`src/llm/prompts.py`, `src/image_utils.py`):**
   - У системний промпт передається компактний довідник закладів, громад і контактів. Ігноруються юрособи оператора та постачальників (*Рамедас Україна*, *Фондако*, *Мистецтво Смаку*, *Школярик*, *Лерчія*, *вул. Січових Стрільців, 12*, *Склад Луцьк 201*).
   - Якщо модель визначила бічний розворот (`90°`/`270°`) або фото розпізналося невпевнено у перевернутому стані (`needs_review`, `legibility != clear` або `confidence < 0.90`), зображення розвертається через `Pillow` і проходить повторне розпізнавання вже рівного аркуша.
6. **Багатофакторне зіставлення з довідником (`src/catalog.py`):**
   - Комбінує ID від моделі, нечіткий пошук `rapidfuzz` по назві та аліасах (з обов'язковою перевіркою номерів ліцеїв `№1`/`№2`), збіг села/адреси (чіткі ТТН за назвою села підтверджуються без `needs_review`), збіг прізвищ кухарів по цілих словах та номер печатки.
   - Загальний поріг впевненості - `CONFIDENCE_REVIEW_THRESHOLD=0.78`.
7. **Самонавчання печаток і прізвищ із захистом від шуму (`src/storage.py`):**
   - Із чітких документів зберігаються прізвища кухарів/директорів (`learned_contacts`, з відсіканням наскрізних прізвищ водіїв, що трапляються >2 разів у різних школах) та круглі печатки (`stamp_registry`).
   - Складські номери на кшталт `201` і не-документні типи фото ігноруються; якщо той самий номер печатки трапляється у двох різних закладів, система **не перезаписує** заклад, а позначає печатку як `is_ambiguous = 1` і припиняє автопідстановку за цим номером.
8. **Узгодження пакета (`album_consensus` та `burst_inherit`):**
   - У межах одного вузького альбому (`<= 2.5с` у тому ж каналі або тому ж Telegram-чаті) одиничне фото контрольної порції або другий листок без шапки успадковує заклад від сусіднього бланка, а схожі за початком назви сторінки вирівнюються за більшістю пакета.
9. **Вирівнювання фото, запис у папки, БД і лог (`src/storage.py`, `src/date_utils.py`, `src/logger.py`):**
   - Кожен файл зберігається одразу (нормалізація EXIF + `rotation_degrees`), дані записуються в `storage/state.db` і `logs/agent.log`.

## Моніторинг у робочий час, ротація `ViberDownloads` та алерти

- **Моніторинг (`src/monitoring.py`, `src/alerts.py`):**
  - У робочий час (`WORK_HOURS_START=09:00` - `WORK_HOURS_END=18:00`, `WORK_DAYS=1,2,3,4,5`) агент відстежує падіння/перезапуски `Viber.exe`, помилки розпізнавання та аномальну тишу (коли нових фото немає довше `SILENCE_ALERT_MINUTES=120` хвилин).
  - Повторні алерти одного типу обмежуються паузою `ALERT_COOLDOWN_MINUTES=60`, усі події фіксуються в таблиці `alert_events`.
- **Ротація старих завантажень (`VIBER_RETENTION_DAYS=21`):**
  - Автоматично при старті/`--watch` (кожні 6 годин) та через `--rotate-old` очищає файли в `ViberDownloads` та `telegram_downloads`, старіші за заданий поріг днів - **лише якщо файл уже має фінальний статус у `storage/state.db`**. Якщо задано `VIBER_ARCHIVE_DIR`, файли переносяться в архів за місяцями замість видалення.

## Встановлення та налаштування (Windows)

1. Клонувати репозиторій:
   ```powershell
   git clone https://github.com/agoloveichuk/ramedas-reports-agent.git
   cd ramedas-reports-agent
   ```
2. Створити віртуальне середовище (Python 3.11+) і поставити залежності через `uv` або `pip`:
   ```powershell
   pip install --user uv
   python -m uv venv --python 3.12 .venv
   python -m uv pip install --python .venv\Scripts\python.exe -r requirements.txt
   ```
   Або стандартним `venv`:
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\pip install -r requirements.txt
   ```
3. Створити `.env` з шаблону:
   ```powershell
   Copy-Item .env.example .env
   ```

### Основні параметри `.env`
| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `GEMINI_API_KEY` | - | Обов'язковий ключ Google AI Studio для базової Vision-цепочки |
| `VIBER_DOWNLOADS_DIR` | автопошук | Папка `ViberDownloads` локального клієнта Viber |
| `REPORTS_OUTPUT_DIR` | локально `./storage/reports` | Цільова папка для `Щоденні документи/` (для сервера: `\\ramedas.local\Public`) |
| `DOCUMENT_DATE_MAX_AGE_DAYS` | `14` | Скільки днів назад дата з бланка вважається валідною |
| `BATCH_WINDOW_SECONDS` | `45` | Пауза очікування досилки фото в один пакет у режимі `--watch` |
| `CONFIDENCE_REVIEW_THRESHOLD` | `0.78` | Нижче цього порогу документ іде в `storage/needs_review/` |
| `VIBER_RETENTION_DAYS` | `21` | Через скільки днів чистити оброблені фото з `ViberDownloads` (`0` = вимкнено) |
| `VIBER_ARCHIVE_DIR` | порожньо | Якщо задано - переносить старі фото туди замість видалення |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | порожньо | Дані User API (`my.telegram.org`) для читання груп Telegram |
| `TELEGRAM_ALLOWED_CHATS` | порожньо | ID або частини назв Telegram-груп через кому (порожньо = всі групи) |
| `TELEGRAM_BOT_TOKEN` / `TECH_ALERT_CHAT_ID` | порожньо | Бот і чат для технічних сповіщень про збої/тишу |
| `WORK_HOURS_START` / `WORK_HOURS_END` | `09:00` / `18:00` | Робоче вікно контролю тиші (`SILENCE_ALERT_MINUTES=120`) |

## Команди запуску та тестування

```powershell
# 1. Діагностика стану (Viber.exe, моделі, Telegram, черга, БД)
.\.venv\Scripts\python.exe -m src.main --status

# 2. Тестовий прогін без запису на диск і в БД (перші 5 фото)
.\.venv\Scripts\python.exe -m src.main --once --limit 5 --dry-run

# 3. Одноразово обробити всю поточну чергу (або обмежену кількість)
.\.venv\Scripts\python.exe -m src.main --once --limit 20
.\.venv\Scripts\python.exe -m src.main --once

# 4. Постійний фоновий моніторинг (бойовий режим)
.\.venv\Scripts\python.exe -m src.main --watch

# 5. Статистика надходжень по годинах і громадах та тест алертів
.\.venv\Scripts\python.exe -m src.main --activity-stats --days 14
.\.venv\Scripts\python.exe -m src.main --test-alert

# 6. Ротація старих файлів у ViberDownloads / telegram_downloads
.\.venv\Scripts\python.exe -m src.main --rotate-old --dry-run
.\.venv\Scripts\python.exe -m src.main --rotate-old --retention-days 14

# 7. Підключення груп Telegram (після заповнення TELEGRAM_API_ID / HASH)
.\.venv\Scripts\python.exe -m src.main --telegram-login
.\.venv\Scripts\python.exe -m src.main --telegram-chats

# 8. Автотести та перевірка синтаксису
.\.venv\Scripts\python.exe -m compileall -q src tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

### Автозапуск на Windows (Task Scheduler)
Для постійної роботи після перезавантаження сервера/ПК створіть задачу в **Планувальнику завдань Windows** під тим самим користувачем, де запущено `Viber Desktop`:
- **Програма:** `C:\...\ramedas-reports-agent\.venv\Scripts\python.exe`
- **Аргументи:** `-m src.main --watch`
- **Робоча папка:** `C:\...\ramedas-reports-agent`
- **Тригер:** При вході користувача в систему (з увімкненим перезапуском при збої).

## Стан тестового прогону та якість (20.11.2026)

- У робочій базі `storage/state.db` накопичено **709** оброблених записів за тестові дні (18-20.11.2026):
  - **642** документи (`matched`) розкладено у дерево `Щоденні документи/` по **121** закладу (усі наявні на диску, `0` втрат).
  - **13** документів (`needs_review`) відкладено на візуальну перевірку (переважно важкий курсивний почерк).
  - **30** файлів (`unmatched`) - переважно одиночні фото страв без бланків поруч і зведені районні таблиці.
  - **20** файлів (`ignored_non_report`) - етикетки продуктів/упаковок.
  - **4** файли (`duplicate`) - відсіяно за `SHA-256` до виклику ШІ.
  - **0** помилок у черзі (`failed = 0`, `processing = 0`).
- База автонавчання містить **52** валідні печатки (ще **9** конфліктних автоматично позначено як `is_ambiguous = 1`, складський код `201` заблоковано) та **529** вивчених контактів кухарів/директорів по **94** закладах.
- Покрито **14 unit-тестами** (`unittest`): дата, короткі назви папок по всіх 385 закладах, EXIF/поворот, чіткі сільські ТТН, пословний пошук прізвищ, гігієна печаток, backoff/черговість роутера, моніторинг тиші/алертів, ротація Viber і наскрізний прогін Telegram + Viber із пакетним успадкуванням.
