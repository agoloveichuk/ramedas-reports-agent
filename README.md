# Ramedas Reports Agent

Скрипт для збору та сортування фотозвітності харчоблоків із груп Viber.

Оскільки офіційний Viber Bot API не вміє читати звичайні групові чати, скрипт забирає фото з локальної папки `ViberDownloads` десктопного клієнта Viber на Windows. Клієнт сам скачує туди фото з груп у фоні, а скрипт розпізнає їх через ШІ, знаходить заклад у довіднику `data/facilities.json` і розкладає по папках.

## Логіка роботи

- Перед відправкою в ШІ рахується SHA-256 хеш файлу, щоб не ганяти і не зберігати дублікати.
- При розпізнаванні ігноруються юрособи компанії (Рамедас, Фондако, Мистецтво Смаку, Школярик, Лерчія), київська адреса і склад Луцьк. Шукається саме школа, ліцей, гімназія або садок.
- Звірка з базою йде за назвою закладу, селом доставки (на ТТН), прізвищем кухаря/директора та номером круглої печатки "Для накладних №...".
- Із чітких актів і меню скрипт сам витягує прізвища кухарів та номери печаток у локальну базу `storage/state.db`. Це дає змогу прив'язувати наступні звіти навіть по тих районах, де в початковому файлі `facilities.json` контакти не заповнені.
- Якщо кухар скидає кілька фото підряд і на одному з них немає шапки (наприклад, фото тарілки зі стравою), воно бере заклад від сусіднього акта чи звіту з цього ж пакета.
- Якщо почерк на бланку важкий і скрипт не впевнений (`score < 0.78`), фото не йде в загальні звіти, а кладеться в `storage/needs_review/` з підказкою кандидата в назві файлу.

## Запуск на Windows

1. Клонувати репозиторій:
```powershell
git clone https://github.com/agoloveichuk/ramedas-reports-agent.git
cd ramedas-reports-agent
```

2. Поставити залежності (Python 3.11+):
```powershell
pip install --user uv
python -m uv venv --python 3.12 .venv
python -m uv pip install --python .venv\Scripts\python.exe -r requirements.txt
```
Або через звичайний venv:
```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```

3. Створити `.env` із шаблону `.env.example`, вписати `GEMINI_API_KEY` і шлях до `ViberDownloads` у `VIBER_DOWNLOADS_DIR`.

## Команди

Статус (чи запущений Viber, які моделі підключені, скільки фото в черзі):
```powershell
.\.venv\Scripts\python.exe -m src.main --status
```

Тестовий прогін на 5 фото без копіювання файлів і без запису в БД:
```powershell
.\.venv\Scripts\python.exe -m src.main --once --limit 5 --dry-run
```

Обробити всю поточну чергу з `ViberDownloads`:
```powershell
.\.venv\Scripts\python.exe -m src.main --once
```

Постійний моніторинг у фоні (також кожні 30с перевіряє процес `Viber.exe` і перезапускає його, якщо закрився):
```powershell
.\.venv\Scripts\python.exe -m src.main --watch
```

## Папки і конфіги

- `storage/reports/<Громада>/<ID_Заклад>/<YYYY-MM-DD>/` - розпізнані звіти
- `storage/needs_review/<YYYY-MM-DD>/` - бланки зі складним почерком на перевірку
- `storage/unmatched/<YYYY-MM-DD>/` - фото без реквізитів закладу (наприклад, одиночні фото страв)
- `storage/ignored_non_reports/<YYYY-MM-DD>/` - відсіяні не-звіти (етикетки продуктів тощо)
- `storage/state.db` - база SQLite з історією обробки, печатками та вивченими прізвищами
- `logs/agent.log` - лог роботи
- `config/llm_routing.json` - список моделей та бекапів (перечитується на ходу без перезапуску скрипта)

## Результати тесту на живих даних (18.11.2026)

Прогнали 255 фото з робочих груп Viber за день. Із них 238 шт. - бланки конкретних закладів, ще 17 шт. - фото страв, етикетки, дублікати і одна зведена районна відомість.

По бланках закладів (238 шт.):
- 229 фото (96.2%) розпізнано чітко і розкладено по папках `storage/reports/`.
- 9 фото (3.8%) з нерозбірливим курсивом (щоденні звіти і розрахунки сировини) відкладено в `storage/needs_review/` з підписаним кандидатом для перевірки очима.
- У нерозпізнані не потрапив жоден бланк школи чи садка.

По решті 17 фото:
- 2 дублікати накладних відсіяно за SHA-256 до виклику ШІ.
- 7 фото етикеток масла, сиру, хека і заморозки відсіяно як не-звіти.
- Із 7 фото готових страв ("контрольні порції") 3 прив'язалися до шкіл автоматично з одного пакета з актами, а 4 одиночні фото без бланків лягли в `unmatched`.
- 1 фото (зведена таблиця овочів одразу на 10 шкіл К-Каширського р-ну) покладено в `unmatched`.

Розподіл по громадах (всього 92 заклади):
- Камінь-Каширський р-н: 106 фото (38 шкіл)
- Любешівська ОТГ: 65 фото (20 шкіл)
- Маневичі + Прилісне ОТГ: 60 фото (24 школи)
- Інші (Підгайці, Колки, Цумань, Сарни, Рівне, Ківерці, Красилів, Гостомель): 10 фото (10 шкіл)

По типах документів:
- Акти харчування: 75
- Щоденні звіти: 53
- Внутрішні накладні (склад Луцьк): 50
- Зовнішні ТТН (хліб та ін.): 37
- Розрахунки сировини: 11
- Заявки: 7
- Меню: 6
- Фото страв і упаковок: 16 (+2 дублікати)

За прогін у базу автоматично зібралося 33 номери круглих печаток "Для накладних №..." та 249 прізвищ кухарів і директорів по 65 школах. Під час піків, коли основна модель (`gemini-flash-lite-latest`, 184 фото) впиралася в хвилинний ліміт, запити автоматично перемикалися на бекап-моделі (`gemini-3.5-flash-lite` - 40 фото, `gemini-3.1-flash-lite` - 32 фото).
